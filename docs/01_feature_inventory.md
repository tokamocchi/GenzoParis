# [1] 機能の棚卸しと MVP スコープ定義

- 入力: `prompts/premise_sheet.md`（前提条件シート）、`prompts/design_prompts.md` のプロンプト [1]
- 位置づけ: たたき台。優先度と難易度は主観的な見積もりなので、レビューで見直す前提です。
- 凡例
  - 優先度: **MVP**（日常的に使い始めるのに必須）／ **v1**（MVP の次に揃えたい）／ **later**（将来）／ **やらない**
  - 難易度: 1（容易）〜 5（非常に困難）。AI が実装する前提での「正しく作り込む難しさ」を示し、作業量の多さとは別です。

---

## 4. 優先度の判断根拠

### MVP に入れないと使い物にならない機能
- **取り込み・一覧・選別・絞り込み**（IMP-01, PRV-01, LIB-01/02/04/05/07）: カタログ管理ツールとしての最低限の機能。50 万枚の規模を前提に、MVP の段階から性能を確保した設計にしておく。後から作り直すと費用が大きい。
- **基本的な現像一式**（DEV-01〜05, 07, 08, 15）: Lightroom の「基本補正」パネルに相当し、日常の現像の大半はこれで完結する。
- **画質と色の土台**（DEV-01, DEV-02, CLR-01）: 重視点の 1 番目。後から差し替えると過去の現像結果がすべて変わるため、最初から作り込む。
- **非破壊編集・履歴・一括適用**（DEV-00, DEV-27, DEV-30）: 大量の写真を現像する前提では、元ファイルを変更しないことと一括適用は必須。
- **データ保全**（SYS-04, FILE-01）: カタログの破損や誤削除は、ツールへの信頼を失う最大の要因になる。
- **動画の登録・サムネイル・メタデータ**（VID-01〜03）: 前提条件で明示された要件。再生（VID-04）は外部プレイヤーで代用できるため v1 にした。
- **回帰テスト基盤**（ORG-04）: AI が保守する前提で品質を保つために必要。

### 見た目は重要そうだが後回しにできる機能
- **マスク・部分補正**（DEV-18, 19）: Lightroom では重要な機能だが、「全体補正だけで使い始められる」ため v1 にした。AI マスクはさらに後。
- **HSL・カラーグレーディング・明瞭度など**（DEV-09〜11）: 作品づくりには重要だが、日常の現像には必須ではない。
- **コレクション・キーワード・スマートコレクション**（LIB-09〜11）: フォルダと評価、フィルターがあれば当面はしのげる。
- **レンズ補正**（DEV-14）: 現行の Sony E マウントのレンズは補正を前提にしたものもあるため、早めに入れたい。それでも MVP の必須条件ではない。v1 の早い段階を推奨する。
- **AI 機能全般**: 前提条件どおり later。ML 推論を差し込める位置だけをアーキテクチャ設計（[4]）で確保しておく。

### 未決事項への提案
- **クラウド同期**: 「やらない」を提案する。1 人 1 カタログで共有が不要なため。複数の PC で使う必要が出てきたら、カタログを外付けドライブで持ち運ぶ方式で対応する。
- **HDR 合成・パノラマ合成**: 「later（要否再検討）」を提案する。難易度が高い一方、専用ソフトで代用できるため。

## 5. MVP の定義（ユーザーストーリー）

MVP は「この状態になれば、日常的に使い始められる」状態とします。

1. SD カードからコピーした ARW と DJI の動画が入ったフォルダを登録すると、すぐにサムネイルが並び、撮影日時順に写真と動画を一覧できる。
2. キーボードだけで ★ や採用 / 不採用を付けながら、次々と選別できる。
3. 「★3 以上」「この期間」「このカメラ」「動画だけ」などで絞り込み、数十万枚のカタログでも待たされずに結果が出る。
4. ARW を開き、ホワイトバランス・露光量・ハイライト / シャドウ・トーンカーブ・彩度・切り抜きで仕上げられる。スライダーを動かすと、プレビューが遅れずについてくる。
5. 調整は元ファイルを変えずに保存される。いつでも元に戻したり、後から調整し直したりできる。
6. 1 枚で作った調整を、同じ状況で撮った複数の写真へまとめて適用できる。
7. 選んだ写真を、サイズと色空間を指定して JPEG で書き出せる。書き出した JPEG は、他のソフトで見てもアプリ上と同じ色に見える。
8. 画面の色はモニターのプロファイルを反映した正しい色で表示される。
9. 動画もサムネイル・撮影日時・長さを確認でき、写真と同じように評価やフィルターができる。
10. カタログは自動でバックアップされ、万一壊れても復元できる。

## 7. 置いた仮定

1. Sony の機種には 60MP 級（α7R 系）も含まれる可能性があるとして、性能の検討では最大 61MP を想定した。実際に使う機種を確認したい。
2. ARW の非圧縮・圧縮・ロスレス圧縮のいずれも使われる可能性があるとした。
3. DJI Osmo Pocket の動画は MP4 / MOV で、H.264 または H.265、8bit または 10bit の可能性があるとした。Log 収録が使われるかは機種と設定次第なので、LUT 適用は later にした。
4. 写真と動画の比率は不明なため、合計で 50 万件として見積もった。
5. カタログは各ユーザーのローカルドライブ（SSD）に置き、写真本体はローカルドライブまたは外付けドライブにあるとした。NAS 上に写真を置く場合は、性能とファイル監視の検討が別途必要になる。
6. 撮影はすべて単写真（Sony の RAW）と動画（DJI）で、スマートフォンの HEIC などは当面対象外とした。
7. Lightroom との互換が不要なため、現像パラメータの意味や数値の範囲は Lightroom に合わせない（操作感の参考にはする）。
