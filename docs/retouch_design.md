# スポット修正（DEV-21。修復・コピースタンプ）の設計

2026-10-26 作成・実装（[実装の進め方と進捗](implementation_status.md) の進捗の No.58）。DEV-21 を v1 に入れて実装することは **利用者の指示**（「DEV-21を実装して」）、ほかは **AI の仮決定（人の確認待ち）** です（決定事項ログ No.202〜205、人の判断の表 No.203〜205）。

**確かめた範囲**: Linux のこのコンテナで、合成の画像・合成の RAW（DNG）・合成の JPEG を使ったテストだけです。**実写（ARW）での見え方・Lightroom Classic との比較・Windows / macOS の実機・アプリの画面（WebView）での操作は確かめていません。** 時間とメモリの計測もしていません。

## 1. 目的と範囲

写真に写ったセンサーのゴミ・電線・小さな写り込みを、まわりの模様で消します。Lightroom Classic の「修復」（スポット修正）に当たります。

| 範囲に含める | 範囲に含めない（later） |
|---|---|
| 修復（コピー元の模様を写し、明るさと色をまわりになじませる）とコピースタンプ（そのまま写す） | 電線・ゴミを自動で見つける（AI。DEV-20 と同じく ML の基盤が要る） |
| 円（クリック）と線（ドラッグ。電線など） | 内容に応じた塗りつぶし（PatchMatch など。コピー元を使わずに埋める） |
| コピー元の自動の選択（まわりがよく似た場所）と、画面でのドラッグ | スポットの可視化（白黒の輪郭表示でゴミを見つけやすくする） |
| 画面（道具・重ねた表示・パネル）・コア API・CLI・一括適用 / プリセットの項目 | 前のスポットの結果をコピー元に使う（2.4 節） |

## 2. 方式

### 2.1 位置の座標: O 座標

スポットの位置・大きさ・コピー元のずれは **O 座標**（RAW の向きを反映した画像（既定の切り抜きの範囲）の長辺を 1 とする座標。左上が (0, 0)。04 の 2.7 節の O）で持ちます。

- マスク（G 座標。回転・歪曲補正の後）と違い、**角度補正・レンズの歪曲補正・切り抜きを後から変えても、スポットは写っているもの（ゴミ・電線）の上からずれません**。1 度の角度補正でも、長辺 6000 画素の写真の端では数十画素動くので、G 座標では小さなゴミから外れてしまいます。
- 画面は、表示している画像の上の 33 × 33 点の O 座標の表（`FrameInfo::o_grid`）を双線形補間して、クリックした位置を O 座標にし、スポットを画像の上に描きます（逆はニュートン法）。回転・歪曲補正があると対応は線形でないので、表にしました。表の細かさは、手動の歪曲補正 ±100 の長辺 6000 画素の写真での補間の誤差（最大 0.64 画素）が、最小のスポットの半径（3 画素）より十分小さくなるように決めました（9 × 9 では最大 9.3 画素ずれて、小さなスポットがクリックした場所から外れました。2026-10-26 の Codex のレビューの指摘で直した。テストで確かめる）。レンズのプロファイルの補正と手動の補正を合わせたときの誤差は確かめていません。

### 2.2 パイプラインの中の位置: 段階 A1 の出力に当てる

スポットは **段階 A1 の出力**（ステージ 8 の後の作業色空間の画像。S の向きの格子）に当てます。O は S を並べ替えて平行移動しただけなので、S の格子の上でスポットの形がそのまま決まります。

| 段階 | スポット修正との関係 |
|---|---|
| A1（センサー処理） | スポットでは作り直さない（キャッシュのキーに入れない） |
| A1 の後（スポットを当てた A1） | エンジンが別にキャッシュする（最新 2 件。キーは A1 のキー・A1 の出どころ（CPU 版か GPU 版の簡易処理か。`A1Origin`）と `DevelopSettings::retouch_hash`） |
| B（ガイド） | スポットを当てた A1 から作る（段階 B のハッシュに、結果に影響するスポットを入れる。ないときは入れないので、ハッシュは足す前と同じ） |
| C（ステージ 9〜17） | スポットを当てた A1 を入力にする |

- **プレビュー**（CPU 版・GPU 版）: `Engine::a1` がスポットを当てた A1 を返します。センサー処理の結果は `Engine::sensor_a1`。WB のドラッグ中の簡易処理（GPU 版）にも `Engine::retouched` で当てます。
- **等倍表示・書き出し**（タイル処理）: タイルのステージ 9 の入力（S の格子のフル解像度の範囲）をセンサー処理で作った後に当てます（`FullResolutionJob::render_source`。GPU 版の書き出しも使う）。コピー元・境界の値は、必要な範囲をその都度センサー処理で作って取ります。
- **処理バージョン**: 処理バージョン 2 から当てます。スポットがなければ結果は足す前とビット単位で同じなので、処理バージョンは上げません。版 1 の写真では当てず、警告を出します（`UnimplementedSetting::Retouch`）。

### 2.3 1 つのスポットの計算

長さは O の画素で扱います。点の列を `P`（1 点なら円、2 点以上なら折れ線）、半径を `r`、ぼかしを `f`、不透明度を `a`、コピー元のずれを `d` とします（式の詳細は `genzo-pipeline` の `retouch` の doc）。

1. **重み**: `P` までの距離が `r(1 − f)` 以下なら 1、`r` 以上なら 0、間は smoothstep。
2. **コピー元の値**: 元の画像（スポットを当てる前の A1）の `p + d` を双線形補間で取ります（画像の外は鏡映）。
3. **修復の補正**: 境界（`P` から `r` より少し外の線）の上の点で、消したい側とコピー元の側のまわりの平均の **比の対数**（チャンネルごと）を求め、内側に補間します。
   - 円: 境界の円の上の点の値を、円の Poisson 核で補間します（円の内側で調和関数になる補間）。
   - 線: 線の両側の値を線に沿って補間し、線を横切る向きに線形に補間します（細い線を想定した 1 次元の調和関数）。
   - 修復の値は `コピー元の値 × 2^補正`。比（掛け算）にしたのは、シーンリニアの値で明るさの違う場所から写すときに、暗い所で負の値になりにくいためです。
4. **合成**: `出力 = 今の値 + (修復の値 − 今の値) · a · 重み`。

画素ごとの値は、格子の全体での座標と元の画像の値だけで決まるので、タイルの分け方・スレッド数によりません（テストで確認）。境界の補正はジョブごとに 1 回だけ求めて、すべてのタイルで使います。

### 2.4 重なったスポット

コピー元と境界の値は、**スポットを当てる前の画像** から取ります（前のスポットの結果は写しません）。タイルの処理で、遠くのコピー元のために前のスポットを計算し直さないためです。重なったスポットは、後のスポットが前の結果の上に重なります。Lightroom Classic と同じかは確かめていません。

### 2.5 コピー元の自動の選択

向き 16 通り × 距離（半径の 2.5・3.5・5 倍）の候補から、コピー元が写真の枠からはみ出す候補と、線のときに消したい線と重なる候補を除き（重なりは、コピー元の線の上に弧長で半径の半分の間隔でとった点で調べるので、点の少ない折れ線で線分が点の間で交わる候補も除く。2026-10-26 の Codex のレビューの指摘で直した）、境界の帯の上の点で輝度の対数の差の 2 乗の平均が最も小さい候補を選びます（`retouch::find_source_offset`）。プレビューの解像度（長辺 2560 画素）の A1 で探します。候補がなければ、画面と CLI は大きさの 2.5 倍だけ横にずらします（この場合は重なりを調べないので、V 字のように大きく曲がった線では重なりうる。画面でコピー元をドラッグして動かす）。

## 3. 設定

```json
{"retouch": [
  {"mode": "heal", "points": [[0.41, 0.22]], "size": 0.01, "offset": [0.03, 0.0]},
  {"mode": "clone", "points": [[0.1, 0.5], [0.6, 0.45]], "size": 0.004, "feather": 30, "offset": [0.0, 0.012]}
]}
```

| 項目 | 範囲 | 既定 |
|---|---|---|
| `enabled` | — | true |
| `mode` | `heal`（修復）・`clone`（コピースタンプ） | `heal` |
| `points` | O 座標。−1〜2。1〜5000 点、線の長さは長辺の 4 倍まで（**仮置き**） | — |
| `size` | 半径。0.0005〜0.25 | 0.01 |
| `feather` | 0〜100 | 50 |
| `opacity` | 0〜100 | 100 |
| `offset` | −2〜2 | — |

- スポットは 1000 個・点は全体で 100,000 点まで（**仮置き**。ブラシのマスクと同じ）。
- 線の長さ（点を順に結んだ折れ線の長さ）は長辺の 4 倍まで（**仮置き**。写真を斜めに横切る線は 1.2 倍ほど）。超える線は検証で拒否し、緩い読み込み（丸め）では超える点から先を除きます。パイプラインは、さらに半径の 1/8 より近い点を間引き（画面は大きさの 1/4 で間引いて送るので、画面の線の点は除かない）、境界の値は 1 回に取り出す範囲を約 400 万画素までにします（いずれも 2026-10-26 の Codex のレビューの指摘で直した。直す前は、画像の外の端どうしを往復する 5000 点の線で、画素ごとにすべての線分を調べて書き出しが終わらない・一度に数 GB の範囲を取り出すことがありえ、大きなスポットの線でも書き出しで 1 GB 近い範囲を取り出していた）。画面は、スポットが 1000 個に達したら新しく描けないようにします（いまのスポットは動かせる）。
- 線の境界の標本は、線に沿って 4096 か所まで（**仮置き**）。とても長い線（点を画像の外の端どうしで往復させたものなど）では標本の間隔を広げ、メモリが際限なく増えないようにします（2026-10-26 の Codex のレビューの指摘で直した。直す前は、検証を通る 5000 点の線で境界の点が約 1 億 2700 万になりえた）。長辺 6000 画素の写真を斜めに横切る線は、最小の大きさでも間隔を広げずに収まります。
- スポットがないときは `retouch` を JSON に書きません（スキーマの版は 2 のまま。設定のハッシュも足す前と同じ）。
- 結果に影響しないスポット（無効・不透明度 0・ずれ 0）は、段階 B のハッシュ・`retouch_hash` に入れません。

## 4. 画面・コア API・CLI

| | 内容 |
|---|---|
| 画面 | 右のパネルの「スポット修正」。道具（Q）を使っている間、プレビューの空いているところをクリックすると円、ドラッグすると線を足します（コピー元はコアが選ぶ）。スポット（実線）・コピー元（点線）をドラッグして動かせます。[ ] で次のスポットの大きさ、Delete / Backspace で選んでいるスポットを除く（写真の削除より先に処理）、Esc で選択を外す・道具を終える。すべてリセットでスポットも除きます |
| 一括適用・プリセット | 項目「スポット修正」。写真ごとに位置が違うので、**既定では写しません**（マスク・切り抜きと同じ）。項目のない JSON（足す前の画面・保存したプリセット）でも写しません |
| コア API | `retouch_auto_source`（コピー元の自動の選択。適用はしない）、`FrameInfo::o_grid`、履歴の名前（「スポット修正を追加」「スポット 2 の不透明度」など） |
| CLI | `genzo develop retouch list / add / set / remove`（`add` で `--source` を省くと自動で選ぶ）、`develop copy --groups retouch` |

## 5. 確かめたこと

- `genzo-pipeline`（単体・結合）: 円・線の修復とコピースタンプ、明るさの違う場所から写したときに修復がまわりに合わせること、斜めの細い線が消えること（相対の差 2% 未満）、タイル（画像の外にはみ出すものを含む）と画像全体でビット単位で同じこと、向き（90 度の回転）でスポットが正しい画素に当たること、版 1 で無視すること、スポットから離れた画素がビット単位で変わらないこと、角度補正・切り抜きでスポットを当てた A1 が変わらないこと、スポットを足してもセンサー処理を作り直さないこと、コピー元の自動の選択。
- IQ-07b の計測値（合成の `wavy_scene` 300 × 201、プレビューの長辺 100。平均・95 パーセンタイル・最大の ΔE2000）: スポットなし 0.211・0.734・6.973、スポットあり 0.378・0.962・38.979。最大はコピースタンプの縁の 1 画素で大きくなります（このシーンでは写した色が元の色とまったく違い、プレビューは縁の重みを画素の中心で決める一方、基準はフル解像度の 3 × 3 画素の平均のため。マスクの縁と同じ種類の差）。スポットを当てた A1 自体は、プレビューとフル解像度でほぼ同じ値でした。
- `genzo-api`・`genzo-cli`（結合）: 合成の JPEG で、描画に効くこと・履歴の名前・O 座標の表（回転なしで G と同じ、回転で中心がほぼ同じ）・コピー元の自動の選択、CLI の追加・変更・削除と書き出しの結果。
- 画面: 計算・道具の流れのテスト（vitest）と、テスト用の見本（MockBridge）で描いた確認用のページ（リポジトリには入れていない）を headless の Chromium で開き、クリックで円・ドラッグで線のスポットが足され、コピー元・スポットのドラッグでずれ・位置が変わることを確かめました。**アプリの WebView では描いていません。**

## 6. 人の確認が必要なこと

- **手法の権利**: 境界の値を内側に調和関数で補間してなじませる手法（Poisson 画像編集・membrane / mean-value の補間に近い）と、コピー元の自動の選択に、特許などの権利が関わるかは調べていません（かすみの除去（DEV-11）と同じく、**AI は判断しません**）。
- **見え方**: 実写（電線・空・センサーのゴミ）での仕上がりと、Lightroom Classic との比較。境界の帯の幅（半径の 1/4）・標本の数・コピー元の候補（向きと距離）は合成の画像だけで決めた仮置きです。
- **時間とメモリ**: スポットが多いとき（数十〜数百）・長い線のとき・フル解像度の書き出しで、M1 Mac・RTX 3080 の実機での計測。数の上限（1000 個・100,000 点）の妥当性。
