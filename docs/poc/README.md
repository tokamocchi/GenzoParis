[05 PoC 計画とロードマップ](../05_poc_and_roadmap.md) の 1 章の PoC-1〜7 の結果を記録する場所です。記録のルールは 05 の 1.8 節「計測と記録のルール」（レビュー R-13）で、このページはその要約と、記録の書き方をまとめたものです。**05 と食い違う場合は 05 を正とします。**

- 作成: 2026-10-10（AI。ひな形）
- 各ページの「目的と合格基準」は 05 からの引用です（2026-10-10 の時点）。05 を変えたときは、各ページの引用も直してください。
- **合否の判定は人が行います**（[実装の進め方と進捗](../implementation_status.md) の「範囲外」）。AI が書くのは、記録欄のひな形と、この環境（Linux のコンテナ）で確認した参考の事項だけです。参考の事項は、各ページの「参考: 実機ではない」の節に分けて書き、判定の欄には書きません。
- 記録の数値・固有名詞（機種・版・日付）は、記録した人とは別の人が確認することを推奨します。

## 2. 計測と記録のルール（05 の 1.8 節の引用）

| 項目 | ルール |
|---|---|
| 入力 | サンプルの ID とファイルのハッシュ、使った現像設定（JSON） |
| 環境 | OS のバージョン、GPU とドライバーのバージョン、主要なライブラリのバージョン、ビルドの設定 |
| 条件 | コールド（起動直後・キャッシュなし）とウォームを分ける。計測の回数（応答時間は 30 回以上、一括処理は 5 回以上） |
| 報告する値 | 平均、95 パーセンタイル、最大。フレームレートは、目標の時間を超えたフレームの数も報告する |
| 応答時間の定義 | **入力イベントの時刻から、画面に表示された時刻まで**。GPU の計算時間だけで判断しない |
| 時間の内訳 | RAW の展開、プロセス間の転送、GPU の計算、エンコード、ファイルの書き込みを分けて記録する |
| 解像度 | プレビューは 2560 × 1707（3:2）で固定する。等倍表示・書き出しは元の解像度 |
| 指標の使い分け | **ΔE2000**: 色の正確さ（PoC-4）と、解像度の違う結果の比較（IQ-07b） ／ **8bit 換算の差**: 同じ解像度での CPU 版と GPU 版の数値の比較（IQ-07a）。この 2 つを同じものとして扱わない |
| 目標に届かなかった場合 | 修正案、または目標・範囲の変更を決定事項ログに記録する。未達の項目を「合格」と扱わない |

### 2.1 このリポジトリでの運用（補足）

- **パーセンタイルの定義**: 最近接順位法（`genzo-testkit` の `stats`。観測した値のどれかになる）。表計算ソフトの関数（線形補間）とは値が少し違うので、手で計算する場合も同じ定義を使ってください。
- **コールド**: 05 の定義は「起動直後・キャッシュなし」です。`genzo-testkit` の `Bench::run_cold` は「渡した関数でキャッシュなどの状態を戻してから測る」もので、OS のファイルキャッシュは戻せません。起動直後の時間は、プロセスを起動し直して 1 回ずつ測り、`Bench::from_samples` で渡します（`genzo-testkit` の `bench` の doc）。記録には、どちらの意味のコールドかを書いてください。
- **応答時間**: 入力イベントから表示までの時間は、処理の関数を呼ぶだけでは測れません。UI（PoC-1 の試作）で測った時間を記録します。UI がない段階の処理時間は「処理時間（参考）」として分けて書き、応答時間の目標の判定に使いません。
- **未達の扱い**: 目標を変える・範囲を狭める場合は、[決定事項ログ](../decision_log.md) に追記し、その No を各ページの「決定事項ログへの反映」に書きます。

## 3. 記録の書き方

### 3.1 手順

1. 該当する PoC のページの「目的と合格基準」と「決めること」を読む。
2. サンプルを用意し、ID を付けて、ファイルのハッシュ（SHA-256）を記録する。
   - Windows（PowerShell）: `Get-FileHash -Algorithm SHA256 <ファイル>`
   - macOS: `shasum -a 256 <ファイル>`
   - Linux: `sha256sum <ファイル>`
3. 環境（OS・GPU とドライバー・ライブラリの版・ビルドの設定・コミット）を記録する。
4. 条件（コールド / ウォーム、回数、解像度）を決めて計測する。
5. 結果の表を埋める（平均・95 パーセンタイル・最大、フレームレートは目標を超えたフレームの数も）。生の記録（`genzo-testkit` の JSON など）の置き場所も書く。
6. 計測の後に、元ファイルのハッシュが計測の前と同じであることを確かめて記録する（DATA-01。元ファイルを書き換えていないことの確認）。
7. 人が判定する（合格 / 不合格 / 保留）。未達の項目を「合格」としない。
8. 決定事項ログに反映し、その No を書く。各ページの「決めること」で決まったものは、その行に結果を書く。

2 回目以降の計測は、各ページの「4. 記録」の節を複製して「記録 2」として追記します（前の記録は消さない）。

### 3.2 記録の欄の意味

| 欄 | 書くこと | 例 |
|---|---|---|
| 入力 | サンプルの ID、ファイル名、SHA-256、機種・記録方式、使った現像設定（JSON のファイルとそのハッシュ） | `a7iv-iso100-landscape-001`（ID の付け方は自由。`genzo-testkit` の `InputRef` の doc の例） |
| 環境 | OS とその版、CPU、メモリ、GPU とドライバーの版、LibRaw・lcms2・wgpu・FFmpeg などの版、ビルドの設定（release / debug、機能フラグ）、コミット | 「macOS 15.x、M1、16GB、release、`--features genzo-cli/libraw`、コミット xxxxxxx」 |
| 条件 | コールド / ウォームと、その意味（2.1 節）、計測の回数、ウォームアップの回数、解像度、そのほか結果に影響する設定（GPU のバックエンド、電源の設定など） | 「ウォーム、ウォームアップ 3 回、30 回、2560 × 1707」 |
| 結果 | 平均・95 パーセンタイル・最大、目標、目標を超えた回数、時間の内訳 | — |
| 判定 | 合格 / 不合格 / 保留、判定者、日付、理由 | — |
| 決定事項ログへの反映 | 追記した No と要旨。反映しない場合はその理由 | 「No.xx: IQ-07b の目標を…に変更」 |

### 3.3 注意

- **サンプルデータの扱い**（05 の 3 章「注意：サンプルデータの扱い」）: このリポジトリは OSS として公開する予定です。人物が写った写真、自宅の位置がわかる GPS 情報を含む写真を、リポジトリに入れないでください。RAW ファイルは公開されない別の保存場所に置きます。記録には、ファイルのパス（ユーザー名や場所が含まれうる）ではなくサンプルの ID とハッシュを書きます。
- **原本の保護**: サンプルの原本は別の場所に保管し、計測には複製を使うことを推奨します（誤って上書き・削除しても戻せるように）。共有フォルダに置く場合は、書き込みの権限を絞ってください。
- **環境の違う記録を直接比べない**: 性能の数値は環境で大きく変わります。`genzo-testkit` の記録（`BenchRecorder`）は、環境が比べられる記録（`EnvironmentInfo::comparable_with`）とだけ前回の値と比べます。
- **合成データ・この環境の値**: 4 章のとおり「参考: 実機ではない」として分けて書き、判定に使いません。

## 4. 計測に使える道具

### 4.1 現在あるもの

**`genzo-testkit`**（[crates/genzo-testkit](../../crates/genzo-testkit)。M0 タスク 11・12）

| モジュール | 用途 |
|---|---|
| `bench`（`Bench`・`BenchRecorder`） | 1.8 節の回数の規則（応答時間 30 回以上・一括処理 5 回以上）を確かめ、平均・95 パーセンタイル・最大と、目標を超えた回数を出す。時間の内訳（`PhaseTimer`）。結果は環境変数 `GENZO_BENCH_DIR`（既定 `bench-results/`。`.gitignore` 済み）に JSON で追記し、前回の結果と比べる（95 パーセンタイルが 10% 以上増えたら悪化とみなす。この 10% は仮置き） |
| `env`（`EnvironmentInfo`） | OS・CPU・ビルドの設定を自動で取得する。GPU とライブラリの版は呼び出し側で設定する。コミットは環境変数 `GENZO_BENCH_COMMIT`（なければ `GITHUB_SHA`） |
| `record`（`InputRef`・`sha256_file_hex`） | 入力の ID と SHA-256、使った現像設定の記録 |
| `diff` | 8bit 換算の差（IQ-07a）と ΔE2000 の平均・95 パーセンタイル・最大（IQ-07b、PoC-4） |
| `colorchecker` | ColorChecker Classic の基準値（D50 → Bradford で D65）。**X-Rite の原本とは未照合**（PoC-4 のページ） |

**計測用のテスト**（通常のテストでは実行しない `#[ignore]` のもの。コマンドは各ファイルの doc のとおり）

| コマンド | 内容 | 関係する PoC |
|---|---|---|
| `cargo test -p genzo-pipeline --release --test engine_bench -- --ignored --nocapture --test-threads 1` | CPU 版: 段階 C（2560 × 1707）、段階 A1 と α7 IV の寸法（7008 × 4672）の書き出し。合成データ | PoC-3（参考） |
| `cargo test -p genzo-gpu --release --test bench -- --ignored --nocapture --test-threads 1` | GPU 版: 段階 C、WB のドラッグ（A1 の簡易処理）、JPEG の書き出し（既定は 1/4 の面積、`GENZO_BENCH_EXPORT_FULL=1` で α7 IV の寸法）。呼び出しから結果が CPU に戻るまでの時間で、表示までの時間ではない | PoC-3 |
| `GENZO_REQUIRE_GPU=1 cargo test -p genzo-gpu` | CPU 版と GPU 版の一致テスト（IQ-07a）。GPU がなければ失敗にする（指定しなければスキップ）。CI のランナー（環境変数 `CI`）では、この指定がないと比較を飛ばす | PoC-3 |
| `cargo test -p genzo-pipeline --release --test engine -- --ignored preview_matches_downscaled_full_resolution_iq07b --nocapture` | IQ-07b の判定（合成画像。現在は未達で失敗する。PoC-5 のページ） | PoC-3・PoC-5 |
| `cargo test -p genzo-color --release report_lut_accuracy -- --ignored --nocapture` | 3D LUT と lcms2 の直接変換の差（格子数ごと） | PoC-1 |
| `GENZO_POC6_ASSETS=500000 cargo test -p genzo-catalog --release -- --ignored poc6 --nocapture` | ダミーの asset（既定 10 万件）の登録、代表的な検索の時間と実行計画、DB と WAL の大きさ、評価の一括変更など。`GENZO_POC6_ANALYZE=1` で検索の前に `ANALYZE` を実行する | PoC-6 |

- `poc6` の計測は、OS の一時ディレクトリにカタログ DB とそのバックアップ（同じくらいの大きさ）を作り、終わると削除します。50 万件では DB とバックアップを合わせて数 GB になりうるので、空き容量を確かめてから実行してください（カタログ DB の上限の目標は 5GB。SCL-02）。
- 結果は標準出力（または標準エラー出力）に表示されます。`engine_bench`・`bench` は、`GENZO_BENCH_DIR` を設定したときだけ `genzo-testkit` の形式で記録を書きます（リポジトリの中にファイルを作らないため）。
- GPU の選び方は環境変数 `GENZO_GPU`・`WGPU_BACKEND`・`WGPU_ADAPTER_NAME`・`WGPU_POWER_PREF`・`GENZO_GPU_ALLOW_SOFTWARE` で変えられます（`genzo-gpu` の `context` の doc）。記録の「条件」に、使ったアダプターの名前とバックエンドを書いてください。

### 4.2 CLI（`genzo`）

検証用の CLI（`genzo`。ORG-05）です（2026-10-10 に実装。引数と出力の詳細は `genzo --help` と `crates/genzo-cli/src/lib.rs` の doc）。計測は release ビルドで行ってください（debug ビルドの記録には「debug」と残り、参考値になります）。RAW（ARW）を入力にするときは、機能フラグ `libraw` を有効にしてビルドします。

| 機能（ORG-05） | コマンドの例 | 使う PoC |
|---|---|---|
| 計測 | `genzo bench preview --file DSC00001.ARW --out bench-results`（段階 C・WB のドラッグ・離した後の最終品質）、`genzo bench export --file DSC00001.ARW`（書き出しの時間の内訳）。`--file` がなければ合成の RAW（`--synthetic 7008x4672`）。回数を省略すると 1.8 節の規則の最小値（応答時間 30 回・一括処理 5 回）。記録は genzo-testkit の形式の JSON で、前回の記録と比べる | PoC-2・3・5・6・7 |
| 登録 | `genzo catalog init`、`genzo import <フォルダ>` | PoC-6・PoC-7 |
| 検索 | `genzo search --min-rating 3 --json` など | PoC-6 |
| 現像・書き出し | `genzo develop set <ID> --json settings.json`、`genzo export <ID> --out <フォルダ>`、カタログなしの `genzo render <ファイル> --out <ファイル>` | PoC-3・PoC-4 |

- `bench` の時間は、呼び出しから結果が戻るまでで、1.8 節の定義（入力から画面への表示まで）ではありません。UI での計測は PoC-1・PoC-3 で行います（`genzo-cli` の `bench` の doc）。
- 入力の長辺が 2560 未満のときは、プレビューが 1.8 節の解像度にならないため、警告を出して、実際のプレビューの寸法を記録します。

## 5. 合成データでの確認と実機での確認の違い

| 観点 | 合成データ・この環境（AI が確認） | 実機・実データ（人が確認） |
|---|---|---|
| 目的 | 処理の正しさ、回帰の検出、仕組み（再起動・タイムアウト・キャッシュなど）が動くこと | **合格基準の判定** |
| 入力 | `genzo-testkit` の合成画像（グレーの階段・ゾーンプレート・細い線・エッジ・ColorChecker の計算値）、合成 DNG、FFmpeg の `lavfi` で作った短い動画、ダミーのカタログ | α7 IV / α7C の ARW（記録方式ごと）、カラーチャートの撮影、DJI Osmo Pocket の動画、実際の写真から作ったサムネイル |
| 環境 | Linux のコンテナ。GPU は Mesa の llvmpipe（CPU で動く Vulkan のソフトウェア実装） | Windows 11 ＋ RTX 3080、M1 Mac（メモリ 16GB）（決定事項ログ No.12・No.20） |
| 性能 | **判断に使えない**（特に GPU。llvmpipe の数値は実機と無関係） | PERF-xx の判定 |
| 色 | 計算値どうしの比較（3D LUT と lcms2、CPU 版と GPU 版など） | カラーチャートの撮影での色差（IQ-04）、目視、OS 標準のビューアとの比較 |
| OS 固有の動作 | Linux だけ（Windows・macOS は CI の clippy とテストだけ） | 両 OS（表示倍率・IME・ファイルシステム・共有メモリ・プロセスの終了など） |
| 記録での扱い | 各ページの「参考: 実機ではない」の節に書く。判定の欄には書かない | 「4. 記録」の欄に書き、判定する |
