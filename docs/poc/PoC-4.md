## 3. この環境で AI が確認した事項（参考: 実機ではない）

この環境の構成は [README](README.md) の 5 章です。**カメラの色変換の評価（IQ-04）は、実際のカラーチャートの撮影がないため行っていません。判定には使いません。** 下の数値は、コードの式と定数から計算したもの、またはテスト・doc に書かれたものです。

- **ステージ 15 の白**（`finish/scene_to_display.rs` の式と、膝 `K = 0.5`）: 輝度 `Y ≤ K` は変えない（中間グレー 0.18 はそのまま）。`Y > K` は `f(Y) = K + (1 − K)·t/(1 + t)`（`t = (Y − K)/(1 − K)`）で、シーンの 1.0 → 0.75、4.0 → 0.9375。0.75 を IEC 61966-2-1 で符号化すると約 0.881、8bit で約 225（量子化のディザリングで ±1 変わりうる）。JPEG の 255 の白と、RAW の飽和した部分（ステージ 3 で「共通の白 = WB の係数の最小値」に切りそろえた白。係数がすべて 1 以上なら 1）は、既定の設定ではシーンの 1.0 になるので、どちらも約 225 になります。
- **RAW 以外の入力の原色**: sRGB の JPEG の (255, 0, 0) は、ステージ 15 では変わらない（輝度が膝より低い）が、書き出し（ステージ 17b、sRGB）の色域の圧縮で、色域の境界（`t = 1`）から `t' ≈ 0.912` に寄せられ、約 (247, 37, 37) になります（ディザリングの前の値。`genzo-color` の `gamut.rs` の式と既定値から計算。各 crate の報告の値とも一致）。
- **色温度の跳び**: 4000 K の前後で基準の白の Duv が約 0.0028（tint 約 8.3）跳ぶことを、テスト（`genzo-color` の `white_balance.rs` の `discontinuity_at_4000k_is_pure_tint_offset`）で確認しています。低い色温度で tint を大きく正にすると、白の色度がスペクトル軌跡の外になりうること、白のカメラ RGB が 0 以下になると係数を作れずエラーになることは、同じファイルの doc とテストにあります（どの組み合わせで起きるかはカメラ行列によります。各 crate の報告で例として挙がったのは 2000 K・tint +150 で、実際のカメラ行列での再現は**要確認**）。
- **コントラスト −100**（`finish/exposure.rs` の式。傾き γ = 0.6）: RGB に掛ける倍率は `exp2((γ − 1)·(L − L0))`（`L = log2(max(Y, 2^−16))`、`L0 = log2(0.18)`）で、中間グレーより暗いほど大きくなります。式から計算すると、輝度が 2^−16 以下の画素で約 42 倍です。暗部では輝度が小さくてもチャンネルの値が正負に散らばるため、その色の成分も同じ倍率で大きくなります。
- **ColorChecker の基準値**: `genzo-testkit` の値（2014 年 11 月の前と後の 2 種類）は colour-science 0.4.6 のデータと一致（2026-10-10）。X-Rite の原本とは未照合。
