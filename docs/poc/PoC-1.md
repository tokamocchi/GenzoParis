## 1. 目的と合格基準（05 からの引用）

| 項目 | 内容 |
|---|---|
| 目的 | 案 A（Tauri 2）と案 B（Rust ネイティブ UI）のどちらにするかを決める（AR-1, AR-2） |
| 検証内容 | (1) Tauri 2 のウィンドウで、wgpu で描画した画像の上に透明な WebView を重ね、スライダーなどの UI を表示する ／ (2) モニターの ICC プロファイルを取得し、lcms2 で作った 3D LUT を適用して描画する ／ (3) OS による色変換が二重にかからないサーフェスの設定 |
| サンプルデータ | 色の基準になる画像（sRGB と Display P3 のテスト画像）、PoC-2 で展開した ARW |

| チェック表（レビュー R-17） | ① 表示倍率 100% / 150% / 200%（Windows）と Retina（Mac） ② 表示倍率の異なるモニター間の移動 ③ ビューポート上でのズーム・パン・切り抜き枠のドラッグ（WebView を重ねた状態でマウス操作が正しく届くか、画像の座標が正しいか） ④ キーボードのフォーカスとショートカット ⑤ ビューポートの上に重ねた入力欄での日本語 IME ⑥ メニュー・ダイアログ ⑦ 最小化と復帰 ⑧ GPU の再初期化（デバイスの消失）からの復帰 ⑨ Windows で HDR が有効なモニターでの SDR 表示 ⑩ グリッドのサムネイル（WebView）とビューポートの色の差 |

| 想定工数 | 2〜3 週 |
| 不合格の場合 | (a) ビューポートを別のネイティブ子ウィンドウにする方式を試す ／ (b) 案 B（Slint などの Rust ネイティブ UI）に切り替え、**同じチェック表** で検証する（＋2〜3 週） |

## 3. この環境で AI が確認した事項（参考: 実機ではない）

この環境の構成は [README](README.md) の 5 章です。**判定には使いません。**

- **UI の試作はまだありません**（Tauri・ビューポート・モニターのプロファイルの取得は未着手）。チェック表と応答時間は、この環境では確認していません。
- **3D LUT と lcms2 の直接変換の差**（`genzo-color` の `lut.rs` の doc。変換元は BT.2020・IEC 61966-2-1、格子は 33³。ΔE2000 の最大。`report_lut_accuracy` のテストで再現できる）。「色域内」「全体」は、変換元の値で一様な乱数 20 万点と、無彩色・暗部・原色の軸の点（色域の圧縮なし。「色域内」は変換先のリニアな RGB と直接変換の出力がどちらも 0〜1 に収まる点）。「圧縮後」は、ステージ 17a と同じ手順（色域の圧縮 → 符号化 → LUT）で B3 の一様な乱数 30 万点（暗部の点は少ない）:

  | 変換先 | 色域内 | 色域内で L* ≥ 5 | 全体 | 圧縮後 |
  |---|---|---|---|---|
  | sRGB（v4.3） | 0.48 | 0.48 | 0.48 | 0.50 |
  | Display P3（v4.3） | 0.34 | 0.34 | 0.34 | 0.33 |
  | リニア BT.2020 | 0.44 | 0.44 | 0.44 | 0.16 |
  | Adobe RGB（ガンマ 563/256） | 1.21 | 0.61 | 1.85 | 0.48 |
  | ガンマ 1.8 のモニターの例 | 0.92 | 0.55 | 1.31 | 0.35 |
  | sRGB v2.4（4096 点の表） | 0.47 | 0.47 | 0.47 | 0.50 |
  | sRGB v2.1（1024 点の表。Windows の既定に似せたもの） | 0.48 | 0.48 | 0.48 | 0.50 |
  | Display P3 v2.4（4096 点の表） | 0.34 | 0.34 | 0.34 | 0.33 |
  | Display P3 v2.1（1024 点の表） | 0.34 | 0.34 | 0.34 | 0.33 |

  格子数を 65 にすると、Adobe RGB の色域内で 0.65（全体で 0.84。同じ doc）。実際のモニターのプロファイルでの値は未確認です。
- **トーンカーブが表のモニターのプロファイル**（2026-10-10、指摘 F36）: v2 のプロファイルのトーンカーブ（2 点以上の 'curv'）では、lcms2 の変換の出力が 0〜1 に収められます。以前は LUT の格子点も収められ、色域の境界の近くの明るい色で誤差が増えていました（修正前の「圧縮後」は sRGB v2.4 で 1.54、Display P3 v2.4 で 1.38）。matrix-shaper のプロファイルでは格子点を範囲の外へ延長するよう直し、上の表のとおり v4 と同じ程度になりました。**LUT 型のプロファイル（BToA などのタグを使うもの）は延長していません**（既知の制約）。Windows の既定の「sRGB IEC61966-2.1」が v2・1024 点の表であることは、一般に知られた情報によるもので、この環境では実物を確認していません（**要確認**）。
- **「色域内」の判定の修正**（同じ日）: 以前の表の Adobe RGB 1.85・ガンマ 1.8 の例 1.31（色域内とされていた値）は、lcms2 が負の値を 0 に収めた、色域のわずかに外の暗い色を含んでいました。直接変換の出力だけでなく変換先のリニアな RGB も見るよう判定を直し、上の表の「色域内」と「全体」に分けました。
- **ICC の版の差**: 生成するプロファイルの v2.4（伝達関数は 4096 点の表）と v4.3 の差は、ΔE2000 で 0.05 未満（`genzo-color` の `icc.rs` の doc とテスト）。
- **ステージ 17a の 0〜1 の外れ**: 色域を圧縮した後でも、LUT の格子点との四面体補間で結果がわずかに 0〜1 から外れる（sRGB とみなしたモニターで、B3 の輝度 0〜1 の範囲で最小 −0.016 程度。シアンの境界の近くの鮮やかな色）。実装では最後に 0〜1 に収めています（`genzo-pipeline` の `finish/output.rs`）。
