# 前提条件シート（記入済み）

`design_prompts.md` の各プロンプトの `{{前提条件シート}}` に、下のコードブロックを貼り付けて使います。
内容を変更したら、決定事項ログにも記録してください。

```
# プロジェクト前提条件
- プロジェクト名: GenzoParis
- 目的: Lightroom Classic 相当の写真現像（RAW 現像・非破壊編集）とカタログ管理（取り込み・選別・検索・整理）を行うデスクトップアプリを自作する
- 利用者: 社内・身内の数名（各自が自分の PC で使う）
- 配布形態: 限られたメンバーへの配布（インストーラーで配布できれば十分。ストア配布は不要）
- ライセンス方針: OSS として公開する。GPL のライブラリも使用可
- 対象 OS: Windows 11 / macOS（Apple Silicon）。Linux・Intel Mac・Windows 10 は対象外
- 開発者の PC: Windows 11（メモリ 32GB、RTX 3080）／ M1 Mac（2021 年頃購入）
- 想定ライブラリ規模: 1 人あたり写真 10万〜50万枚（動画を含む）
- 主な撮影機材 / ファイル形式:
  - 写真: Sony α7 IV（約 33MP）、α7C（約 24MP）／ ARW
  - 動画: DJI Osmo Pocket（MP4 / MOV 想定。コーデック・ビット深度は機種と設定により異なるため要確認）
- 動画の扱い: カタログ管理の対象とする（取り込み、サムネイル・プレビュー、メタデータ表示、レーティング、キーワード、検索）。動画の編集機能は当面不要
- 保存場所: カタログ・写真本体とも PC の内蔵ドライブ
- カタログの共有: 不要。Lightroom Classic と同様に 1 人 1 カタログ
- Lightroom との互換性: 不要（既存カタログからの移行も XMP の読み書きも求めない）
- 開発体制: AI が主に実装・保守し、人はレビューと方針決定を行う
  - 技術選定では、AI が正しく扱いやすいことを重視する（型が強い、コンパイラやテストで誤りを検出しやすい、情報量の多い技術、自動テストしやすい構成）
- 開発者のスキル: 特定の言語にこだわらない（上記の AI 保守前提で選定してよい）
- 想定期間: 特に期限なし（段階的に育てる）
- 予算: 未定（無償の OSS ライブラリを優先し、有償のものは必要性を示したうえで提案すること）
- AI 機能: MVP には入れないが将来入れたい（AI マスク、AI ノイズ除去など）。後から組み込める設計にする
- 重視すること（優先順）:
  1. 画質・色の正確さ（デモザイク品質、カラーマネジメント）
  2. 全体の操作・動作の軽快さ（現像スライダーの応答、大量の写真・動画の閲覧と検索）
- やらないこと: テザー撮影、印刷・フォトブック、クラウド同期、Web 公開・Web ギャラリー、スライドショー
- 未決: HDR・パノラマ合成の要否（現在は later・要否再検討）、スマートフォン写真（HEIC など）の扱い
```

## 検討時に AI に注意させたい論点（この前提から導かれるもの）

- **動画のカタログ管理**: サムネイル生成・メタデータ取得・プレビュー再生の手段（FFmpeg など）の選定。FFmpeg はビルド構成によって LGPL か GPL になる点と、H.265 などの特許の扱いを確認すること
- **GPL 可の OSS**: Exiv2 など GPL のライブラリも候補にできる。その代わり、アプリ全体のライセンスをどれにするかを決める必要がある
- **Lightroom 互換が不要**: 現像パラメータやカタログのスキーマを自由に設計できる
- **写真 10万〜50万枚**: グリッド表示・検索の性能と、プレビューキャッシュの容量管理が重要になる
- **Windows / macOS**: GPU API の違い（DirectX 12 / Metal）と、モニタープロファイルを適用した表示の実現方法
- **AI による保守**: 自動テスト（特に画像処理結果の回帰テスト）を最初から設計に組み込むこと
